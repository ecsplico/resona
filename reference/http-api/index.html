    HTTP API (client contract)¶

    The published client contract of resona-api: every route with the client audience tag and the schemas those routes use (ResonaAPI.openapi_client()). Admin, evaluation, testbench and worker routes are internal and not part of it. The machine-readable document is committed as contract/openapi.json and published here as openapi.json; info.version is the hub release id.

    • Regenerate after changing a client route or schema: just contract (uv run python scripts/gen_openapi.py). packages/api/tests/test_contract.py fails on a stale document and names that command.
    • CI job contract (.github/workflows/test.yml) compares the committed document with the one at the latest v* tag (oasdiff breaking --fail-on ERR). A pull request with a breaking change fails unless it carries the label contract-break; pushes to main only report. A tag that predates contract/openapi.json is skipped with a notice.
    • This page is rendered from the committed document at docs build time by the MkDocs hook scripts/mkdocs_openapi.py (no network).

    Contract version 0.2.8 (OpenAPI 3.1.0).

    POST /v1/audio/transcriptions¶

    Operation id: audio_transcriptions_create

    Create Transcription

    OpenAI-compatible speech-to-text as a bounded wait on a queued audio job.

    Multipart fields: file plus OpenAI model, language, response_format (json|text|verbose_json), prompt/temperature (ignored) and Resona engine, execution_profile, profile, private (default true), diarize (label speakers, needs a worker that diarizes; default: the execution profile's diarize), webhook (name of an active webhook endpoint notified when the job ends). Admission is identical to POST /v1/jobs.

    Parameter In Type Required Description
    Idempotency-Key header string or null no
    Status Description Body
    200 The transcript: JSON, or plain text with response_format=text. application/json: TranscriptionResponse
    text/plain: string
    400 Error: invalid_idempotency_key. application/json: JobErrorBody
    401 Error: unauthorized. application/json: JobErrorBody
    403 Error: forbidden, policy_denied. application/json: JobErrorBody
    404 Error: upload_not_found, execution_profile_not_found, profile_not_found, job_not_found. application/json: JobErrorBody
    409 Error: idempotency_conflict, settings_missing, job_cancelled. application/json: JobErrorBody
    410 Error: content_unavailable. application/json: JobErrorBody
    413 Error: too_large. application/json: JobErrorBody
    415 Error: unsupported_media. application/json: JobErrorBody
    422 Error: invalid_upload, empty_upload, invalid_request, invalid_options, invalid_instructions, invalid_profile, kind_mismatch, no_candidates, unapproved_override, unknown_webhook. application/json: JobErrorBody
    502 The job failed: error is the job's own error code (open set, e.g. unsupported_input), job_failed when it has none. application/json: JobErrorBody
    504 Error: timeout. The job keeps running; job_id and the Location header name it. application/json: JobErrorBody

    DELETE /v1/jobs/{job_id}¶

    Operation id: jobs_delete

    Delete Job

    Delete a job in any state; later reads are 404 at once.

    A pending or terminal job's row, idempotency keys and files go now. A processing job is cancelled first: its lease is fenced (the worker's next call is stale_lease), its input removed, and its row kept as an invisible deleted tombstone until the replaced lease would have expired, so a late worker cannot resurrect it; the maintenance sweep then purges it.

    Parameter In Type Required Description
    job_id path integer yes
    Status Description Body
    204 Successful Response
    401 Error: unauthorized. application/json: ErrorBody
    403 Error: forbidden. application/json: ErrorBody
    404 Error: job_not_found. application/json: ErrorBody
    422 Error: rejected parameters. application/json: ValidationErrorBody

    StageProvenance¶

    One executed stage. In-process stages record the accelerator actually used; endpoint stages (llm via an approved endpoint) record endpoint_id and accelerator='external' because the endpoint process owns its device. accelerator='auto' marks an in-process stage whose device the operating system selects and does not report (Apple Vision OCR may use CPU, GPU or Neural Engine); it records that the device was not observed, not that it was a GPU.

    peak_accelerator_bytes is the peak device memory (CUDA allocator / MLX) of the execution process, recorded on stages that ran on cuda/metal; stages run together by one engine call (Docling layout + table structure) share the value.

    Field Type Required Description
